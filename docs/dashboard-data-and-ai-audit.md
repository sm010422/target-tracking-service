# 대시보드 정보 감사 — 무슨 데이터를, 어떻게 만들어서, AI가 뭘 해주고, 결과가 뭔가

`static/index.html`에 AI 위협분석 모달과 챗봇 패널을 연결한 뒤(`docs/concepts/03-dashboard-ai-integration.md`), "그래서 이 화면에서 실제로 얻을 수 있는 정보가 뭔가"를 처음부터 끝까지 추적한 감사 기록. 개선 우선순위까지 정리한다.

## 1. 데이터가 어디서 생기나 — 지금은 전부 가상 데이터

```java
// DroneSimulator.simulate()
targetId: DRONE-001/002/003 중 하나 (고정된 3개뿐)
latitude/longitude: 한반도 범위 내 완전 랜덤
altitude: 100~1000m 랜덤
speed: 50~250km/h 랜덤
status: 항상 "DETECTED"
```

실제 센서 데이터가 아니라 순수 난수다. "시뮬레이션 실행" 버튼을 누르면 이 랜덤값이 그만큼 생성된다. 중요한 건 — 매 라운드마다 좌표가 그냥 랜덤으로 다시 뽑히는 거라, 화면에서 드론이 "이동"하는 것처럼 보여도 실제로는 물리적으로 이어지는 궤적이 아니라 **매번 새로 찍히는 점들**이라는 것. 지도에 경로선이 그려지긴 하지만 그건 최근 20개 랜덤 좌표를 이어 그린 선일 뿐, 드론이 실제로 그 경로로 비행했다는 물리적 근거는 없다.

## 2. 데이터가 어떻게 가공되나 — 두 갈래로 갈라짐

```
DroneSimulator → Kafka(target-tracking 토픽)
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
target-tracking-service    threat-intel-ai-service
(Java, 같은 서비스)          (Python, 별도 서비스)
        │                       │
   WebSocket 브로드캐스트      Qdrant에 "이력"으로 영구 저장
   → 지도/사이드바 실시간 표시   (챗봇이 나중에 검색할 데이터)
        │
   PostgreSQL에도 저장
   (지금 대시보드는 이걸 화면에 안 씀 — /api/targets는 있지만 호출 안 함)
```

같은 Kafka 이벤트 하나가 서로 다른 두 소비자에게 각자 다른 목적으로 쓰인다 — 실시간 시각화(Java, WebSocket)와 이력 축적(Python, Qdrant)이 완전히 독립적으로 진행된다.

## 3. AI가 정확히 뭘 해주나 — 서로 다른 두 종류

| | AI 위협분석 버튼 | AI 챗봇 패널 |
|---|---|---|
| 비교 대상 | **고정된 10개 패턴** (앱 시작 시 미리 심어둔 지식베이스) | **실제로 쌓인 탐지 이력** (Qdrant, Kafka로 누적) + 업로드한 문서 |
| 입력 | 지금 보이는 표적 1개의 현재 값 | 자유 텍스트 질문 |
| 출력 | 위협등급 뱃지 + SITREP 문장 + 유사패턴 3개 텍스트 | 자연어 답변 + 근거 출처 + (조건부) 도구 호출 결과 |
| 언제 유용한가 | "이 표적 지금 위험한가?" | "과거에 이런 적 있었나?", "교리상 어떻게 대응하나?" |

하나는 "지금 이 순간의 표적을 정적 기준과 비교"하고, 다른 하나는 "실제로 쌓인 과거 이력/문서에서 답을 찾는" 것이라 성격이 다르다. 문제는 **화면상으로는 둘이 완전히 분리돼 있어서, 사용자가 이 차이를 알 방법이 없다**는 것 — 버튼 이름과 패널 제목만으로는 "왜 두 개나 있는지"가 전달되지 않는다.

## 4. 최종 결과물

지도 위 드론 아이콘 + 사이드바 카드(원시 수치) + (버튼을 누르면) 위협등급 모달 또는 챗봇 답변. 사용자가 아무 버튼도 안 누르면 원시 좌표/고도/속도 숫자 나열 이상의 정보는 얻을 수 없다.

## 5. 개선 포인트 (우선순위 순)

1. **데이터가 가짜라는 걸 아무도 모른다** — 시연 중 "이거 실제 센서 데이터예요?"라는 질문에 애매해진다. 화면에 "SIMULATED DATA" 배지를 박아두는 게 안전하다.
2. **한눈에 보이는 위협 요약이 없다** — 표적이 여러 개면 하나씩 다 눌러봐야 위험도를 안다. 사이드바 상단에 "🔴 CRITICAL 1건, 🟡 MEDIUM 2건" 같은 집계 배너가 필요하다.
3. **지도 위에서 위협도가 안 보인다** — 아이콘이 전부 동일한 ✈️다. 위협분석을 돌린 표적은 마커 색을 등급별(빨강/주황/노랑)로 바꾸면 훨씬 "지휘통제"다워진다.
4. **챗봇의 존재 이유를 사용자가 못 알아챈다** — 첫 안내 문구 하나뿐이라, "DRONE-001 위협 등급 평가해줘"처럼 tool-calling을 유도하는 질문을 쳐야 한다는 걸 아무도 모른다. 예시 질문 칩(chip) 2~3개를 미리 깔아두는 게 좋다.
5. **궤적이 물리적으로 말이 안 된다** — 매 라운드 완전 랜덤 좌표라 "드론이 날아온다"는 서사가 약하다. 이전 위치 근처에서 조금씩 이동하는 랜덤워크로 바꾸면 설득력이 붙는다 (`DroneSimulator` 수정 필요).
6. **이력 기반 정보가 시각화 안 된다** — Qdrant에 쌓인 실제 이력(같은 표적이 몇 번 탐지됐는지)이 챗봇에 물어봐야만 나온다. 표적 카드에 "이 표적, 과거 N회 탐지됨" 한 줄만 붙여도 챗봇 없이 바로 보인다.

1~4번은 프론트엔드(대시보드) 수정만으로 가능하고, 5~6번은 각각 Java 시뮬레이터 로직과 Python 조회 API가 추가로 필요하다.
